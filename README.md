# TaskbarMedia

أداة شخصية صغيرة لـ Windows 11 تضع **مشغّل وسائط داخل شريط المهام**: أيقونة بغلاف الأغنية بجانب الساعة، وشريط تحكم سريع عند تمرير الماوس، ولوحة كبيرة عند الضغط على الغلاف. تعمل مع أي مصدر يشغّل صوتًا أو فيديو ويعرّف نفسه لـ Windows (YouTube في المتصفح، YouTube Music، Spotify، مشغل الوسائط...).

الفكرة مستوحاة من ميزة "Taskbar Widget" في [FluentFlyout](https://github.com/unchihugo/FluentFlyout) (مفتوح المصدر، GPL-3.0). درسنا طريقة عملها وكتبنا نسخة مبسطة خاصة بنا تحتوي هذه الميزة فقط.

> للاستخدام الشخصي، والمستودع خاص.

---

## ما الذي تفعله

| الطبقة | متى تظهر | ماذا فيها |
|---|---|---|
| **1. الأيقونة** | ما دام هناك مصدر تشغيل (حتى أثناء الإيقاف المؤقت) | غلاف الأغنية بحجم أيقونة، بجانب الـ tray |
| **2. الشريط السريع** | عند تمرير الماوس على الأيقونة | غلاف + العنوان + الفنان + السابق / تشغيل-إيقاف / التالي |
| **3. اللوحة الكبيرة** | عند الضغط على الغلاف في الشريط السريع | غلاف كبير + العنوان + الفنان + خلط / سابق / تشغيل / تالي / تكرار |

**تفاصيل الشكل والسلوك:**
- **لون الأغنية:** الشريط السريع واللوحة يأخذان لونهما من غلاف الأغنية، بانتقال ناعم عند تغيّرها. لون النص (أبيض أو أسود) يُختار تلقائيًا ليبقى مقروءًا، والأغلفة الرمادية تُبقي ألوان الثيم العادية.
- **التطابق مع شريط المهام العائم:** إذا كان شريط المهام عائمًا بزوايا دائرية (مثل تعديلات Windhawk)، يصطف الشريط السريع مع حافته ويأخذ نفس شكل الكبسولة.
- **التلاشي مع الـ tray:** الأيقونة تختفي بتلاشٍ عند ابتعاد الماوس عن منطقة الـ tray، وتظهر عند اقترابه. تبقى ظاهرة ما دام الشريط السريع أو اللوحة مفتوحًا.
- **الإخفاء التلقائي:** إذا كان شريط المهام يختفي تلقائيًا، تختفي الأيقونة معه.
- **الخلط والتكرار:** يعملان فقط إذا كان التطبيق المشغِّل يدعمهما (Spotify نعم، YouTube في المتصفح غالبًا لا). عند عدم الدعم يظهران باهتين، وهذا حد من Windows نفسه.
- **التكرار** يدور بين: بدون تكرار ← تكرار الكل ← تكرار الأغنية.
- **العناوين المتحركة:** العنوان أو اسم الفنان إذا كان أطول من المساحة ينزلق ذهابًا وإيابًا (وقفة، انزلاق، وقفة، عودة)، فقط والشريط أو اللوحة ظاهرة. النص العربي يُعرض ويتحرك من اليمين لليسار، فيظهر أول العنوان لا آخره.
- **Windows العربي:** يدعم شريط المهام المعكوس (الساعة على اليسار).
- **الإغلاق:** زر الماوس الأيمن على الأيقونة ← "خروج".
- **التشغيل مع Windows:** تسجّل الأداة نفسها تلقائيًا عند أول تشغيل للـ EXE.

## الإعدادات

كلها من **الزر الأيمن على الأيقونة**، وتُطبَّق فورًا وتُحفظ في `%AppData%\TaskbarMedia\settings.json` (الملف المفقود أو التالف يعيد القيم الافتراضية):

| الخيار | الافتراضي | ماذا يفعل |
|---|---|---|
| إخفاء في وضع ملء الشاشة | مفعّل | تختفي الأيقونة ويُغلق الشريط السريع عندما تغطي نافذة (فيديو، لعبة) الشاشة كاملة، وتعود بالخروج منه |
| إظهار تلقائي عند تغيير الأغنية | معطّل | يظهر الشريط السريع 4 ثوانٍ عند تغيّر الأغنية |
| تفعيل الاختصار | مفعّل | **Ctrl+Alt+M** تخفي الأيقونة أو تُظهرها يدويًا |
| لون التمييز | لون الألبوم | "لون الألبوم" أو "لون ويندوز" لتلوين الشريط السريع واللوحة |
| الموضع | تلقائي | تلقائي (بجانب الـ tray) أو أعلى الوسط، أو إحدى زوايا الشاشة الأربع |

## التشغيل

1. شغّل `dist\TaskbarMedia.exe` (أو حمّله من صفحة الـ Releases في المستودع).
2. يحتاج **.NET 8 Desktop Runtime** (موجود مسبقًا إذا كان .NET 8 SDK مثبتًا).
3. عند أول تشغيل تُضاف الأداة إلى بدء التشغيل، فتعمل تلقائيًا مع كل دخول إلى Windows.

**إزالتها من بدء التشغيل:** احذف القيمة `TaskbarMedia` من المفتاح:
```
HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run
```
أو أوقفها من "إدارة المهام" ← "تطبيقات بدء التشغيل".

> إذا نقلت الـ EXE إلى مكان آخر وشغّلته من هناك، يُحدَّث مسار بدء التشغيل تلقائيًا. نسخ التطوير (أي شيء داخل مجلد `bin`) لا تسجّل نفسها أبدًا.

## البناء

يحتاج .NET 8 SDK.

```bash
dotnet build TaskbarMedia -c Debug
```

بناء EXE واحد في مجلد `dist`:

```bash
dotnet publish TaskbarMedia/TaskbarMedia.csproj -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true -p:DebugType=none -o dist
```

حجم الـ EXE حوالي 25 MB لأنه يضم مكتبة Windows للوسائط (`Windows.Media.Control`).

## بنية المشروع

| الملف | دوره |
|---|---|
| `App.xaml(.cs)` | نقطة البداية: نسخة واحدة فقط، إنشاء الأيقونة، وإعادة إنشائها إذا أُعيد تشغيل Explorer |
| `MediaService.cs` | قراءة جلسة الوسائط الحالية من Windows (GSMTC) وإرسال الأوامر، مع إعادة المحاولة إن فشل الاتصال عند البدء |
| `TaskbarWidget.xaml(.cs)` | الأيقونة فوق شريط المهام: الموضع، والتلاشي، والإخفاء التلقائي، وفتح الشريط السريع |
| `QuickBar.xaml(.cs)` | الشريط السريع عند التمرير |
| `NowPlayingPanel.xaml(.cs)` | اللوحة الكبيرة |
| `ColorExtractor.cs` | استخراج اللون الغالب من الغلاف وجعله صالحًا كخلفية |
| `Palette.cs` | ألوان الشريط واللوحة (من الغلاف أو من الثيم) مع الانتقال الناعم |
| `Popups.cs` | وضع الشريط واللوحة فوق شريط المهام داخل حدود الشاشة |
| `MarqueeText.cs` | سطر نص ينزلق عند طوله، مع دعم اتجاه العربية |
| `Theme.cs` | قراءة الثيم الفاتح/الداكن ولون Windows المميز |
| `Autostart.cs` | التسجيل في بدء التشغيل |
| `Native.cs` | تعريفات Win32 المستخدمة |
| `app.manifest` | دعم DPI لكل شاشة (PerMonitorV2) وتوافق Windows 10/11 |

## كيف تعمل (تقنيًا)

- **مصدر الوسائط:** `GlobalSystemMediaTransportControlsSessionManager` يعطي العنوان والفنان والغلاف وحالة التشغيل، وعبره تعمل الأزرار.
- **الأيقونة نافذة "مملوكة" لشريط المهام** (`GWLP_HWNDPARENT = Shell_TrayWnd`) وليست نافذة داخله. النافذة المملوكة تبقى دائمًا فوق مالكها، وتُوضع بإحداثيات الشاشة العادية.
- **مكان الـ tray الحقيقي** يُقرأ عبر UI Automation (`SystemTrayIcon` و`NotifyItemIcon`)، لأن نافذة `TrayNotifyWnd` القديمة لا تعطي العرض الصحيح في Windows 11. وحافة شريط المهام العائم تُقرأ من `TaskbarFrame`.
- **مؤقتات المتابعة:** كل 1.5 ثانية لإعادة قياس الـ tray، وكل ربع ثانية لإرجاع الأيقونة إن تحركت أو لمتابعة الإخفاء التلقائي، وكل 0.1 ثانية لتلاشي الأيقونة حسب مكان الماوس.

## مشاكل واجهناها وحلولها

| المشكلة | السبب | الحل |
|---|---|---|
| انهيار عند البدء أحيانًا | فشل الاتصال بخدمة الوسائط في بعض البيئات | إعادة المحاولة كل 2 ثانية تتباعد حتى 30 ثانية |
| الشريط فوق الساعة في Windows العربي | شريط المهام معكوس (RTL) والساعة على اليسار | حساب الموضع حسب اتجاه شريط المهام |
| تغطية أيقونات الـ tray | `TrayNotifyWnd` أضيق من الـ tray الحقيقي في Windows 11 | قراءة الـ tray عبر UI Automation |
| تغطية أيقونات التطبيقات | المساحة الفارغة صغيرة | تحويل الشريط إلى أيقونة واحدة + شريط عند التمرير |
| نافذة الأيقونة أعرض من اللازم | Windows يفرض حدًا أدنى لعرض النوافذ (~132 نقطة) | خفض الحد الأدنى عبر `WM_GETMINMAXINFO` |
| وميض الأيقونة عند التمرير | كنافذة داخل شريط المهام المعكوس، كان WPF يضعها في الموضع المعكوس مع كل إعادة رسم | تحويلها إلى نافذة مملوكة فوق شريط المهام |
| اختفاء الأيقونة بعد إعادة تشغيل Explorer | النافذة تُدمَّر مع شريط المهام القديم ولا يُبلغ WPF بذلك | فحص دوري لوجود النافذة وإعادة إنشائها |

## ملاحظات

- **الاختبار بأدوات التحكم بالشاشة:** بعض أدوات التقاط الشاشة أو التحكم الآلي تصغّر النوافذ غير المسموح بها مؤقتًا. أضفنا استعادة تلقائية لهذه الحالة، فلا تؤثر على الاستخدام العادي.
- **تغيير مقياس الشاشة:** الأداة مبنية لإعادة القياس عند تغيّره، لكنه لم يُختبر يدويًا بعد.
- **أفكار مستقبلية:** أيقونة خاصة للتطبيق.
